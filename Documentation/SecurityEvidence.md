## Implemented evidence

| Control | Reviewable source / validation |
| --- | --- |
| Public-client OAuth with PKCE | Native callback state and loopback validation; managed token proxy fixes the public client ID, restricts grant fields and callback format, and rejects duplicate form fields. [Account client](../Sources/YapMeetings/ZoomAccountClient.swift), [service](../Services/zoom-auth/src/index.ts). |
| SDK signing authorization | HMAC-authenticated, expiring authorization binds the exact access-token SHA-256 and public client ID. Signing additionally verifies live access through Zoom's ZAK endpoint. The SDK secret stays in a service secret binding. An arbitrary supplied OAuth token cannot obtain a signature without the matching grant. [Service](../Services/zoom-auth/src/index.ts), [negative and positive tests](../Services/zoom-auth/test/auth.test.ts). |
| Network and input limits | Fixed Zoom upstreams; no upstream redirects; 15-second upstream timeout; bounded request and provider-response bodies; HTTPS-only service endpoints except local tests. Recording loaders validate response types and bounded content, and strip OAuth authorization before a non-Zoom CDN redirect. [Service](../Services/zoom-auth/src/index.ts), [media loader](../Sources/YapAppUI/RecordingMediaLoader.swift). |
| Service retention and abuse controls | No application database or durable store for user credentials or meeting content. The static asset binding serves public documentation and images; authentication tokens exist transiently in request processing. Rate-limit keys use hashed source IPs or access tokens: 120 requests/minute and 10 signatures/minute. Explicit application error events are constant; invocation logs and traces are disabled. Cloudflare infrastructure metadata and rate-limit state are separate from application retention. [Deployment configuration](../Services/zoom-auth/wrangler.jsonc). |
| Local storage and content separation | Account credentials use macOS Keychain. Zoom meeting media and recording/chat/transcript downloads go directly between the Mac and Zoom/CDN, not through the signer. User exports and calendar cache have the retention and file protections explained in [Privacy](../PRIVACY.md). |

## CodeQL configuration and coverage

The Swift job selects the repository's Xcode 26.6 toolchain (Swift 6.3.3), initializes CodeQL, then performs a fresh manual arm64 build of the `Yap` product. CodeQL 2.26.2 explicitly added Swift 6.3.3 support. The workflow uses action v4 with current tools so it does not rely on an older bundled compiler extractor. [Exact compiler support](https://codeql.github.com/docs/codeql-overview/codeql-changelog/codeql-cli-2.26.2/), [manual Swift build guidance](https://docs.github.com/en/code-security/reference/code-scanning/codeql/build-options-for-compiled-languages)

JavaScript/TypeScript analysis uses the no-build mode. GitHub supports CodeQL scanning in public repositories; the workflow uploads language-specific results to the repository's code-scanning view. Keep the emitted CodeQL version and analysis logs with the run evidence. [Workflow options](https://docs.github.com/en/code-security/reference/code-scanning/workflow-configuration-options)

Coverage is limited to what each extractor analyzes. The public Swift build intentionally omits the proprietary Zoom SDK and the conditional SDK bridge path. CodeQL does not support Objective-C/Objective-C++, so the native bridge is not covered by this workflow. Vendor binaries, Apple/Zoom internal behavior, Cloudflare's platform, complete framework-specific behavior, and deployed configuration are not independently assessed by these scans. Manual review and actual-SDK tests remain necessary. [Supported languages and frameworks](https://codeql.github.com/docs/codeql-overview/supported-languages-and-frameworks/)
