## SDK package required

Zoom distributes current macOS SDK packages through its authenticated Marketplace. In a General app, enable **Features → Embed → Meeting SDK**, select macOS, and download the current Apple silicon package. Save the downloaded package into `Whoosh/Vendor/Zoom/` and keep its original directory structure. The public `zoom-sdk-macos` repository points to Marketplace for current downloads; its old releases are not a substitute for a supported SDK. [Download instructions](https://developers.zoom.us/docs/meeting-sdk/macos/get-started/), [official repository](https://github.com/zoom/zoom-sdk-macos).

Do not paste credentials into source files, commit vendor secrets, or copy private frameworks out of the installed Zoom client. Whoosh's personal build imports the owner's development credentials into this Mac's Keychain and signs the short-lived SDK JWT at runtime. That owner-only path is unsuitable for distributing shared developer credentials; public distribution needs a trusted signing service. Never bundle the client secret in the app. [Meeting SDK credentials](https://developers.zoom.us/docs/meeting-sdk/get-credentials/).

## Authentication and personal-use access

There are separate layers: SDK application authentication, the human's Zoom identity, and permission to enter a particular meeting. Whoosh uses the human identity/ZAK path, including host access, rather than a bot identity. An SDK JWT alone does not provide a user's hosting authority. Meetings outside the developer account require the applicable Zoom app review and authorization even when Whoosh is only for personal use. Test an account-owned meeting first, then externally hosted meetings once authorized. [Authorization FAQ](https://developers.zoom.us/docs/meeting-sdk/obf-faq/).

### Personal Zoom configuration

In the user-managed General app, enable **Use Public Client OAuth**, register `http://127.0.0.1/callback` as the native loopback redirect, and add the granular scopes `user:read:zak` and `meeting:write:meeting`. The latter allows Whoosh to create a meeting for the signed-in user when they choose Start a meeting; no administrator meeting-write scope is requested. Zoom's native PKCE loopback matching ignores the ephemeral port while requiring the registered path/host to match. The app uses the public OAuth Client ID for browser sign-in, with a fresh state and S256 verifier; it separately uses the regular Client ID and Client Secret for SDK signing. Standard confidential OAuth clients do not qualify for HTTP loopback. [Native PKCE and loopback](https://developers.zoom.us/docs/integrations/oauth/), [Meetings API](https://developers.zoom.us/docs/api/meetings/).

In Whoosh Settings, choose **Enter Zoom configuration…**, enter the regular **Client ID**, paste the **Client Secret** into its native secure field, and enter the **Public OAuth Client ID**. Save configuration writes directly to a non-synchronizing, unlocked-device-only Keychain item. The secret field clears immediately on Save and all fields clear on dismissal. Existing configuration can be replaced from its settings menu; replacement disconnects the saved Zoom authorization and requires sign-in again. Configuration changes are disabled during calls and connection mutations.

JSON import remains available. The schema below uses labels, not actual credentials; manual entry avoids creating an additional plaintext credential file.

```json
{
  "sdkClientID": "REGULAR_CLIENT_ID_FROM_ZOOM",
  "sdkClientSecret": "CLIENT_SECRET_FROM_ZOOM",
  "oauthPublicClientID": "PUBLIC_CLIENT_ID_FROM_ZOOM"
}
```

`ZoomAccountClient.configure(fromJSON:)` imports this configuration. `connect(openURL:)` opens the system browser, verifies the loopback response, exchanges the code, validates ZAK access, and saves rotating OAuth credentials. `meetingCredentials()` obtains a fresh five-minute ZAK from `/v2/users/me/zak` immediately before joining and makes a one-hour native SDK JWT. `hostingCredentials(title:)` also creates an own-user instant meeting via `POST /v2/users/me/meetings` with `type: 1` and returns its numeric ID alongside fresh SDK credentials. `disconnect()` removes local OAuth credentials; `removeConfiguration()` also removes the imported developer settings. Disconnect does not claim to revoke Zoom's server-side app authorization. [Authenticated-user ZAK endpoint](https://developers.zoom.us/docs/api/users/), [native SDK JWT format](https://developers.zoom.us/docs/meeting-sdk/auth/), [Meetings API](https://developers.zoom.us/docs/api/meetings/).

The created room uses host and participant video off, mute upon entry, waiting room on, join before host off, and no personal meeting ID. Automatic recording, meeting summary, and AI Companion questions are explicitly off. Whoosh sends no invitations. The prepared room ID is reused across retries until the SDK confirms InMeeting; cancellation after a confirmed creation retains that ID. An uncertain creation result blocks another POST until an explicit reconnect, avoiding duplicate meetings. Missing creation permission produces a reconnect/setup error instead of widening authorization silently.

Token-bearing HTTP requests refuse redirects and use an ephemeral session. Error messages omit response bodies and token values. OAuth/token/meeting-creation unit tests use fixtures. Separately, real account authorization, ZAK retrieval, SDK host startup, and incoming camera video from an independent Zoom endpoint have been verified through Whoosh. The broader real-call acceptance matrix below remains in progress.

## Native bridge implementation contract

`ZoomMeetingDriver` implements the `MeetingDriver` boundary through the `WhooshZoomBridge` target. The app should construct it using `makeZoomMeetingDriver(accountClient:)` with the same actor used by its Zoom connection settings. `MeetingCoordinator` owns visible state and rejects callbacks tagged with a different session UUID. The driver must own the SDK instance, callback delegates, native video elements, and subscriptions for the whole session. SDK callbacks must be marshaled onto the main actor before calling `onEvent`; copy scalar values before crossing threads rather than sending SDK objects between actors.

The native boundary is Objective-C and compiles against the downloaded public SDK headers. The Swift wrapper receives copied, in-memory event payloads on the main actor. SDK logging remains disabled. Native consent sheets retain the SDK-provided text and require a person to act; Whoosh does not silently accept recording or archiving notices.

| Whoosh operation | Current documented SDK surface | Implementation requirement |
|---|---|---|
| Initialize custom UI | `ZoomSDKInitParams.needCustomizedUI`, `[ZoomSDK sharedSDK]`, `initSDKWithParams:` | Choose custom UI before initialization. Keep SDK logging off in normal use. |
| Authenticate application | `ZoomSDKAuthContext.jwtToken`, `ZoomSDKAuthService.sdkAuth`, auth delegate | Wait for successful asynchronous authentication; obtain a fresh signed identity for each meeting attempt. Fail closed if muted-on-entry cannot be confirmed after authentication. |
| Join | `ZoomSDKMeetingService.joinMeeting:` with `ZoomSDKJoinMeetingElements` | Pass the meeting ID/passcode or supported vanity ID and user ZAK; preserve the source link only in memory. |
| Host | `startMeetingWithZAK:` with `ZoomSDKStartMeetingUseZakElements` | Use `SDKUserType_APIUser`, the real meeting ID returned by the own-user REST creation, and valid host ZAK. |
| Leave/end | `leaveMeetingWithCmd:` | Distinguish local leave from ending for everyone; wait for actual terminal state. |
| Native participant tiles | `getVideoContainer`, `createNormalVideoElement:`, element `userid`, `getVideoView`, `resize:`, `setResolution:` | Bind only when the camera-on view is attached with usable bounds. Setting `userid` starts the initial subscription; do not immediately duplicate it with `subscribeVideo:YES`. Coalesce rate-limit failures into bounded delayed retries. Release off-page subscriptions and clean elements on leave. |
| Camera quality and tile labels | `enableCatchHDVideo:`, `isCatchHDVideoOn`, `getVideoStatisticInfo`, `displayUserNameOnVideo:` | Request HD on explicit camera activation; distinguish the preference from observed send resolution/FPS. Hide Zoom's native name/mute decoration before renderer creation because Whoosh supplies its own accessible overlay. |
| In-meeting chat | `getMeetingChatController`, `sendChatMsgTo:`, chat delegate | Use supported recipient/message objects; represent host-disabled chat correctly. |
| Sharing | `getASController`, `startAppShare:`, `startMonitorShare:`, `stopShare`, `getShareContainer` | Install the AS controller delegate on confirmed InMeeting: the controller does not exist before admission. Only show “Sharing” following SDK confirmation. |

## Build and signing

The package must build with Xcode 26 or later for SDK 7+. Link `ZoomSDK.framework` and the exact companion libraries declared in the downloaded package. A local SwiftPM target can receive the framework search path and `.linkedFramework("ZoomSDK")`; the app packaging step must additionally copy and sign the framework, dylibs, and SDK helper/plugin bundles in the locations required by the sample. Do not assume copying a single framework is sufficient. Confirm all binaries support arm64 and the app loads from a clean launch outside the development directory. Zoom's current macOS SDK does not support App Sandbox, so Whoosh targets Developer ID signing and notarization. [SDK setup and packaging](https://developers.zoom.us/docs/meeting-sdk/macos/get-started/).
