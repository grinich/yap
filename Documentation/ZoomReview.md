Yap is an independent macOS application for people who use Zoom for meetings. ## Exact scopes and functional justification

Current client source: [ZoomCredentials](../Sources/YapMeetings/ZoomCredentials.swift), [ZoomAccountClient](../Sources/YapMeetings/ZoomAccountClient.swift). Select these **user-level granular scopes**, not their `:admin` or `:master` alternatives. The [signer](../Services/zoom-auth/src/index.ts) requires the same three scopes and adds none.

| Scope | Endpoint / data | Copyable justification |
| --- | --- | --- |
| `user:read:zak` | `GET https://api.zoom.us/v2/users/me/zak`; the signed-in user's five-minute ZAK. | Obtain the consenting user's ZAK immediately before starting or joining a meeting, so the native Meeting SDK acts as that user. No other account member's ZAK is requested. |
| `meeting:write:meeting` | `POST https://api.zoom.us/v2/users/me/meetings`; instant meeting ID and creation result. | Create an instant meeting only when the user chooses to host. The SDK then starts that meeting with the user's ZAK. The app does not create meetings for other users or send invitations through this API. |
| `cloud_recording:read:list_user_recordings` | `GET https://api.zoom.us/v2/users/me/recordings`; paginated meeting/file metadata and returned download URLs. | List the consenting user's cloud recordings so they can search, play and save completed videos and read available saved chat/transcript files. Authenticated file downloads use the returned URLs; the app does not delete or change cloud recordings. |

Zoom documents these endpoints and granular scopes in its [Users API](https://developers.zoom.us/docs/api/users/) and [Meetings API](https://developers.zoom.us/docs/api/meetings/). The app does not call the separate meeting-transcript REST endpoint, so do not request `cloud_recording:read:meeting_transcript` merely because the player displays a downloaded VTT file. Cloud recording controls during a live meeting use SDK permission APIs rather than a recording-write REST scope.

## Technical design and data paths

**Client architecture — verified in source:** Swift/SwiftUI and AppKit interface; Objective-C bridge to Zoom Meeting SDK 7.1.5 (84750); Foundation URLSession for REST/downloads; AVPlayer with a resource loader for authenticated playback; CryptoKit for PKCE; macOS Keychain for app credentials; Sparkle for signed updates. No RTMS, meeting bot, AI model or advertising integration is implemented.

1. The Mac opens Zoom authorization in the user's system browser. It generates random state and an S256 PKCE verifier/challenge, then receives the code on a temporary listener bound only to `127.0.0.1` and an ephemeral port. It validates state, path, Host and a single authorization code, then closes the listener. **Personal mode** exchanges/refreshes directly with `https://zoom.us/oauth/token`. **Managed mode** sends the code, verifier and redirect, or a refresh token, to the configured HTTPS service at `/v1/oauth/token`; the service pins the production public client ID and forwards only accepted fields to Zoom.
2. The Mac calls Zoom's REST APIs with the user's access token. REST transport uses ephemeral sessions without URL/cookie storage and refuses redirects. Refresh operations are coalesced; account generation checks prevent a late response from restoring disconnected credentials.
3. In managed mode, the Cloudflare Worker returns the Zoom access/refresh tokens and an HMAC-signed authorization grant bound to the access token's SHA-256 hash and the configured public client ID. The Mac saves these in Keychain. To get an SDK JWT, it sends the access token and grant to `/v1/meeting-sdk/signature`. The Worker verifies the grant and makes a fresh `GET /v2/users/me/zak` request to Zoom before signing a native SDK JWT with its server-held secret. Personal mode instead signs locally using the owner's imported developer configuration. ZAK and the SDK JWT have separate functions. [SDK authorization](https://developers.zoom.us/docs/meeting-sdk/auth/)
4. The native SDK exchanges live meeting audio, video, shared screens, participant metadata and in-meeting chat with Zoom. The project-operated signer must not be described as carrying this media. The SDK's recording permission/consent handling and Apps and privacy panel remain available through the bridge.
5. Recordings are listed by monthly date windows and paginated. Playback/text requests begin at validated HTTPS Zoom media URLs. HTTPS CDN redirects drop the Zoom OAuth Authorization header outside trusted Zoom hosts. Video uses bounded byte ranges with an 8 MiB per-loader memory cache; fallback playback can use a temporary file. Chat/transcript inputs are limited to 8 MiB each, validated for content type/encoding and rejected if they are HTML/auth pages.
6. Optional Google Calendar OAuth and reads run directly between the Mac and Google. User-initiated links and bug reports open in the browser. Configured updates contact the release host through Sparkle; system-profile sending is disabled.

**Production PKCE explanation — copyable:**

This is a native macOS application using Zoom's public-client OAuth PKCE flow. It cannot safely hold a confidential OAuth client secret. Register `http://127.0.0.1/callback` in the public client's redirect allow list; the application supplies a fresh ephemeral port for each authorization. Only the port varies. Browser consent, S256, cryptographically random state, a loopback-only listener and exact callback validation protect the flow. A same-origin HTTPS token proxy forwards the PKCE exchange/refresh using the fixed public client ID and issues token-bound signing authorization; it does not use confidential-client OAuth credentials. The separately held SDK secret signs SDK JWTs only after that authorization and a live ZAK check.

Zoom explicitly documents this loopback flow for eligible native/PKCE clients and may request the production public-client justification above. Use the **Production public client ID** for a first-time review build. [OAuth PKCE and loopback](https://developers.zoom.us/docs/integrations/oauth/#using-a-loopback-redirect-uri), [first-time submission](https://developers.zoom.us/docs/distribute/app-submission/submit-apps-review/)
