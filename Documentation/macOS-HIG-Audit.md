## Window, toolbar, and menu corrections

- Removed the decorative Whoosh logo/name toolbar item beside the native traffic lights. It consumed navigation space without providing navigation or an action. Its absence was confirmed in the newly launched app.
- Kept the standard macOS window controls, resize behavior, and compact unified toolbar. The actual window title now describes the agenda or current meeting for the Window menu and accessibility. Its visible title remains hidden because the content supplies a heading. Preview status uses plain text rather than a custom capsule background.
- Added View → Refresh Calendar and Command-R to match the toolbar command. Chat menu text now describes whether it will show or hide the pane, and the People pane is also available from the Meeting menu.

These changes follow Apple’s guidance to use meaningful content titles, avoid app names as window titles, reduce custom toolbar backgrounds, and make toolbar actions available in menus. [Apple: Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)

- Removed the toolbar Settings button and the duplicate settings sheet. Programmatic setup requests now open the existing native Settings scene; the standard app-menu Settings command and Command-Comma remain available. Removed the misplaced Settings entry from Help.

Apple places app-wide settings in a settings window reached through the app menu and specifically discourages Settings buttons in window toolbars. [Apple: Settings](https://developer.apple.com/design/human-interface-guidelines/settings)

- Replaced the large promotional agenda heading with “Today” using the system large-title style. Reduced the outer content margin to a consistent 24 points; this is a Whoosh layout choice, not a mandated HIG measurement.
- Removed the decorative icon and duplicate top-right close button from the Join sheet. The standard Cancel and default Join actions remain, including Escape and Return. Its heading now uses a system text style.

- The agenda now presents only validated Zoom meeting candidates, with the true empty state when none remain; non-Zoom rows are visibly absent in the live app.
- Invalid pasted links are explained inside the Join sheet, which stays open. Editing or Cancel clears only that local feedback. The reported invalid-link/Cancel path passed live without a delayed global alert. Automated cases also protect unrelated alerts, active-call/busy-account feedback, and muted/camera-off entry.

System text styles provide a consistent hierarchy, and layouts should respect platform margins while adapting to available space. [Apple: Typography](https://developer.apple.com/design/human-interface-guidelines/typography), [Apple: Layout](https://developer.apple.com/design/human-interface-guidelines/layout)

## Settings and in-call corrections

- Removed the repeated logo/name and modal Done button from Settings. The native tabbed Settings scene now restores its selected pane and supplies that pane’s title. Calendar selection uses standard checkboxes. The reminder interval is unavailable while reminders are off. The preview action brings the main window forward.
- Zoom settings explicitly show a saved-connection check while Keychain access is pending. A denied or interrupted initial read offers Retry, and configuration replacement stays disabled while loading. A previously connected account remains usable during background status refresh. Five regression tests cover these distinctions and overlapping status reads. After the signed update, Command-Comma opened Settings with both saved accounts immediately connected. Several subsequent SDK initialization/authentication/hosting attempts worked across changed binaries/quick relaunches without another blocking prompt. A later self-signed build again asked for access to Whoosh's own vault before SDK initialization. Its agenda subsequently refreshed, but the specific prompt cause remains unresolved. Accessibility remained off and untouched; this is not a claim that every OS permission is solved.

Apple recommends a dedicated settings window with clear panes, remembering the selected pane, and platform controls that express settings state. [Apple: Settings](https://developer.apple.com/design/human-interface-guidelines/settings), [Apple: Toggles](https://developer.apple.com/design/human-interface-guidelines/toggles)

- Replaced the custom 76 × 66 vertical call buttons and manually drawn glass/disabled states with macOS 26’s system glass button style. Horizontal symbol-and-text controls adapt to symbol-only controls when the call canvas narrows, preserving all four actions. Tooltips and accessibility labels name the actions; microphone and camera also expose their confirmed state. ScreenCaptureKit previews are bounded, serialized, and kept only in memory while the sheet is open. Selecting an item does not begin transmission; the separate Share confirmation and existing session/capability checks remain in place.
- Camera controls expose the SDK-confirmed HD preference separately from measured outbound dimensions/frame rate. The information is in a tooltip/context menu, preserving the compact main controls. No outgoing resolution is invented when a sample is unavailable.

These styles compiled in the release and their current appearance was captured in the actual app. The home actions were previously verified at the top in the signed app. The native chat composer was exercised: Return sent a message and cleared its input, and messages were verified in both directions with the native Zoom client in the same meeting.

Apple recommends its system sharing picker. [Apple: Content sharing picker](https://developer.apple.com/documentation/screencapturekit/sccontentsharingpicker)
